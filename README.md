# Student Attendance Tracker

A beginner-friendly full-stack college project to register students, mark daily attendance, and review attendance history. The interface is built with HTML, CSS, and Vanilla JavaScript; the backend uses Node.js and Express; persistent data is stored in Supabase PostgreSQL.

## 1. Problem statement

Keeping paper-based attendance registers can make it difficult to find student details and review attendance by date. This application gives a college administrator a simple place to maintain a student directory and save each student's daily status.

## 2. Objectives and users

**Main user:** a single administrator operating a college-project demo.

**Objectives**
- Register students with a unique roll number.
- Edit student details and remove a student when necessary.
- Mark each student present or absent for a chosen date.
- Prevent duplicate attendance rows for the same student and date.
- Search students and review attendance records.

## 3. Implemented features

- Password-protected administrator session.
- Dashboard counts for students, present, absent, and attendance rate.
- Student add, list, search, edit, and delete.
- Daily attendance entry with mark-all-present and mark-all-absent shortcuts.
- Attendance history with date and student search filters.
- Responsive layout and validation/error messages.
- PostgreSQL constraints and indexes.

**MVP limitations:** this is a single-admin classroom project, not a multi-user institutional deployment. It does not provide student logins, exports, biometric attendance, automatic reminders, or multi-admin role management. Express's default in-memory session store is intended for local development only; use a persistent session store before production deployment.

## 4. Technology stack

- HTML5, CSS3, Vanilla JavaScript
- Node.js 20+ and Express.js
- Supabase PostgreSQL via `@supabase/supabase-js`
- Git and GitHub

## 7. Create and configure Supabase

1. Sign in to Supabase and create a new project.
2. Choose a project name and a strong database password; save the password privately.
3. Wait for the database to finish provisioning.
4. Open **SQL Editor** in the Supabase dashboard.
5. Open `database/schema.sql` in VS Code, copy all of it into the SQL Editor, and run it.
6. Open **Table Editor** and verify that `students` and `attendance` exist.
7. Open **Project Settings → API** (the exact menu label can change). Copy the project URL and the server-side service-role/secret key. Keep the key private.

The server uses a privileged key, so all database routes are protected by the admin session middleware. The database tables have Row Level Security enabled and no public policies. Do not put the service-role/secret key in frontend files, GitHub, screenshots, or a public README.

## 8. Configure environment variables

1. In VS Code, open `backend/.env`.
2. Replace `SUPABASE_URL` with your Supabase project URL.
3. Replace `SUPABASE_SERVICE_ROLE_KEY` with the server-side key from your own Supabase project.
4. Change `ADMIN_PASSWORD` to a long, unique password (at least 12 characters).
5. Generate a random session secret using this command from the `backend` folder:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Copy the printed value into `SESSION_SECRET`. Do not use the example placeholders as real credentials.

`.env` contains local secrets and is ignored by Git. `.env.example` documents variable names and safe placeholders; it is intended to be committed.

## 9. Install dependencies

Open the project folder in VS Code. Choose **Terminal → New Terminal**.

In Windows PowerShell, run:

```powershell
cd backend
npm install
npm run check
```

`npm install` downloads the required packages and creates `package-lock.json`. `npm run check` checks JavaScript syntax. A successful check exits without syntax errors.

## 10. Start the application

From the `backend` folder:

```bash
npm start
```

Expected terminal message:

```text
Student Attendance Tracker running at http://localhost:3000
```

Open `http://localhost:3000` in your browser. Sign in using the `ADMIN_PASSWORD` value in `backend/.env`. Add students, then open **Mark attendance**, choose a date, select statuses, and save. Refresh the page to confirm the records persist in Supabase.

For automatic restart while developing, use `npm run dev`.

## 11. Architecture

```text
Browser (HTML/CSS/Vanilla JS)
        | fetch() / JSON
        v
Express backend (admin session + validation)
        | Supabase server-side client
        v
Supabase PostgreSQL (students, attendance)
```

The browser never connects directly to the database. The service-role key stays on the server. RLS is enabled with no public access policies; Express authenticates the administrator before database routes run.

## 12. API reference

All `/api/students` and `/api/attendance` endpoints require a valid admin session cookie. JSON errors use `{ "error": "message" }`.

| Method | Path | Purpose | Body / query | Success |
|---|---|---|---|---|
| GET | `/api/health` | Server health check | None | `{ "ok": true, ... }` |
| GET | `/api/auth/me` | Check session | None | `{ "authenticated": true/false }` |
| POST | `/api/auth/login` | Sign in | `{ "password": "..." }` | `{ "authenticated": true }` |
| POST | `/api/auth/logout` | Sign out | `{}` | `{ "ok": true }` |
| GET | `/api/students` | List students | None | `{ "students": [...] }` |
| POST | `/api/students` | Add student | `full_name`, `roll_number`, optional `course`, `email` | `201 { "student": {...} }` |
| PUT | `/api/students/:id` | Update student | Same fields as create | `{ "student": {...} }` |
| DELETE | `/api/students/:id` | Delete student and attendance | None | `204` |
| GET | `/api/attendance?date=YYYY-MM-DD` | Daily register | Optional date | `{ "records": [...] }` |
| GET | `/api/attendance?search=...` | Search history | Optional `date`, `search` | `{ "records": [...] }` |
| POST | `/api/attendance/bulk` | Save/update statuses | `{ "date":"YYYY-MM-DD", "records":[{"student_id":"uuid","status":"present"}] }` | `{ "saved": 1 }` |

Typical errors: `400` invalid input, `401` not signed in, `409` duplicate roll number, `404` missing student, and `500` unexpected server/database failure.

## 14. Troubleshooting

**The server exits with a configuration error:** check `backend/.env` and ensure `ADMIN_PASSWORD` is at least 12 characters and `SESSION_SECRET` is at least 32 characters.

**Missing Supabase environment variables:** verify `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are set in `backend/.env` with no extra quotes or spaces.

**Invalid API key / database requests fail:** confirm the URL and server-side key belong to the same Supabase project. Never share the key publicly.

**Table not found:** run `database/schema.sql` in the Supabase SQL Editor and verify both table names.

**Port 3000 is already in use:** change `PORT=3001` in `backend/.env` and open `http://localhost:3001`.

**Sign-in keeps failing:** use the exact `ADMIN_PASSWORD` configured in `.env`; restart the server after editing environment variables.

**CSS or JavaScript appears old:** hard refresh the browser with `Ctrl+F5`.

**Dependencies fail to install:** check internet access, then run `npm install` from the `backend` directory with a supported Node.js version.

## 15. GitHub upload

Before uploading, ensure no real secret is committed. From the project root:

```bash
git init
git status
git add .
git status
git commit -m "Build student attendance tracker"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git push -u origin main
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with the URL of your repository. Create an empty repository on GitHub first. Check the second `git status` output to ensure `backend/.env` is not staged and `.env.example` is staged.

If a secret was ever committed, adding `.env` to `.gitignore` is not enough. Rotate the credential immediately and clean repository history before sharing the repository.

## 16. Security and future improvements

This is a learning MVP. Use HTTPS, a persistent session store, a secure secret manager, backups, and a more complete authentication/authorization design before any real institutional deployment. Add CSV export, class/section filters, monthly reports, and student-level logins only if the project requirements call for them.
